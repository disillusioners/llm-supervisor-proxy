## Objective
Verify the entire feature end-to-end with three layers: (a) unit tests for the engine's distribution (BOTH unique-first-message AND templated-first-message), affinity (token-salted keys), TTL, weight-invalidation, race-detector properties, and the W-2 empty-key no-binding invariant; (b) handler integration tests that prove multi-credential models distribute by weight, single-credential models are byte-identical to today with NO binding map writes (E-3), and the engine wiring survives the request lifecycle; (c) an E2E shell script (`test/test_mock_credential_lb.sh`) that exercises two mock upstreams, asserts distribution + affinity + the templated-first-message scenario in-process, and serves as the rollout smoke test. All tests must pass under `go test -race`.

## Context
Phase 1 delivered the schema + store (M-1: migration 028 = ADD + backfill + same-statement derived shadow write to `credential_id`; NO DROP COLUMN; 029 deferred behind release-note deprecation window). Phase 2 delivered `pkg/credentiallb.Engine` with the amended contract from `technical-analysis.md §API Contract` (lines 1349-1373 changelog + amended contract). Phase 3 wired the engine into the request path with the post-auth token-salted conversation key (A-1). Phase 4 added the UI/API surface. Phase 5 is the verification gate. The test plan mirrors the structure already established in `decisions.md §E` (engine unit, handler integration, migration, E2E), with extensions: (1) a templated-first-message distribution test that the original plan's 100-unique-messages test cannot detect; (2) a `test_helpers.go` extension so handler integration tests can drive two distinct upstreams against one model; (3) a manual curl checklist (in-repo, not a separate doc) for the rollout reviewer.

The existing house pattern is:
- **Go unit/integration tests**: `pkg/.../*_test.go`, run via `go test ./...`. Uses `database/sql` + `modernc.org/sqlite` for in-memory DBs (see `pkg/proxy/handler_integration_test.go:30-71` for the `setupIntegrationDB` pattern).
- **Handler integration tests**: `pkg/proxy/handler_integration_test.go` — uses `httptest.NewServer` for upstreams and `models.NewModelsConfig()` for fast config setup.
- **E2E shell scripts**: `test/test_mock_*.sh` — `bash` + `curl` + `go run` for the proxy. The reference is `test/test_mock_ultimate_model.sh` (565 lines): two upstreams on ports 4001/4002, proxy on 4322, `clean_ports` from `test_mock_clean_ports.sh`, `assert_contains` helper, `hard_timeout` trap.
- **Frontend tests**: `pnpm test` (vitest + @testing-library/preact, per `pkg/ui/frontend/package.json`). House pattern is light — most coverage is on the Go side.
- **Mock LLMs**: `test/mock_llm_openai.go` is a real HTTP server that simulates an OpenAI-compatible upstream; supports message-keyed responses for sticky tests.

This phase adds NO production code (with one exception: a tiny helper added to `pkg/proxy/test_helpers.go` to enable multi-upstream handler integration tests). All other work is test files.

1. **Create** engine unit tests `pkg/credentiallb/*_test.go` — mirror `decisions.md §E` tests 1–7 PLUS the **leader-mandated templated-first-message distribution test** and the **W-2 empty-key no-binding test** (per the architect's amendment). Fixed RNG seed for determinism. Each test is small (<200 lines) and named per the contract:
   - `TestEngine_Distribution` — N=10k with unique first-user messages; ±5% tolerance.
   - **`TestEngine_Distribution_TemplatedFirstMessage` (NEW, leader-mandated)** — N=10k requests sharing the SAME first-user message but DIFFERENT `tokenID`s (one per request). Asserts hits distribute across credentials per weights. **This test detects the templated-agent skew failure class that A-1 was introduced to prevent.** Without it, the existing 100-unique-messages test passes while the actual production workload silently pins to one credential.
   - `TestEngine_Affinity` — same `(tokenID, firstUserMessage)` pair → same credential across N calls; `newlyBound=true` on first call, `false` on subsequent.
   - `TestEngine_Affinity_TokenSalted` (NEW, A-1) — same first-user message but DIFFERENT `tokenID`s → DIFFERENT bindings (independent selections per principal). Two distinct tokens sending the same message land on potentially DIFFERENT credentials; the same token sending the same message lands on the SAME credential.
   - `TestEngine_Affinity_Anonymous` (NEW, A-1 graceful degradation) — empty `tokenID` + same first-user message → same credential (the unsalted key binds them).
   - **`TestEngine_EmptyKey_NoBinding` (NEW, W-2)** — two requests with `conversationKey == ""` → MAY pick DIFFERENT credentials (fresh weighted pick per request). The engine's internal binding map size for that model stays 0 (no binding stored). Per C2: empty-key picks return `newlyBound=false` (no binding stored) — the engine NEVER emits, and callers MUST NOT publish `model_credential_selected` for empty-key picks (zero events; DEBUG log is the observability, phase3 Scope #8). (**REVISED 2026-08-21 — reviewer pass C2**; supersedes the prior "event fires per request" reading.)
   - `TestEngine_TTLExpiry` — bind, advance time past TTL, next call returns fresh credential.
   - `TestEngine_WeightChangeInvalidation` — `OnModelChanged` with new weights; **E-2** filter-survivors: bindings whose credential survives are preserved; only orphans dropped.
   - `TestEngine_RaceDetector` — concurrent `GetOrSelect` for distinct + overlapping keys; pass `go test -race`.
   - `TestEngine_NoCredentials` — returns `ErrNoCredentials`; `newlyBound=false`.
   - `TestEngine_SingleCredentialFastPath` — **E-3** asserts the binding map size for that model is **ZERO** after N requests (`Engine.Stats().Bindings(modelID) == 0`); `newlyBound=false` on every call (no binding write).
   - **`TestEngine_ExtractFirstUserMessage_Multimodal` (NEW, A-2)** — multimodal `[]interface{}` content produces a deterministic canonical-JSON hash; the same content yields the same hash; the same content with a different ordering yields a different hash (canonicalization discipline). Pinned to the same credential across N calls.
   - **`TestEngine_JanitorPanicRecovery` (NEW, E-4 recommended)** — inject a panic into one model's sweep path; assert the janitor logs the panic, continues to sweep other models, and does NOT exit the goroutine. Assertable via `Engine.Stats()` showing the panicking model's bindings dropped (other models untouched).
   - **`TestEngine_Stats` (NEW, E-4 recommended)** — `Engine.Stats()` returns sane per-model hits/misses/bindings under load.
   - Run all with `go test -race`.
