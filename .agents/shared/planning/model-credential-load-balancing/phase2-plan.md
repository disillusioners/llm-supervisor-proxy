## Objective

Deliver the `pkg/credentiallb` package exactly per the amended contract's API (`Engine.GetOrSelect`,
`OnModelChanged`, `OnCredentialDeleted`, `RebindFromStore`, `Stop`, `ComputeConversationKey`,
`ExtractFirstUserMessage`, `ErrNoCredentials`): cumulative-prefix-sum weighted random selection,
`(modelID, conversationKey)` binding map with 24h TTL + 5-minute janitor goroutine (outer **RLock**
+ per-model write locks, per E-1), hybrid lazy+proactive invalidation (filter-survivors, per E-2),
the single-credential fast path with **NO map writes** (per E-3), the `newlyBound bool` signal on
`GetOrSelect` (per W-1), empty-key semantics with **no binding stored** (per W-2), and the
recommended per-model RNG + `Engine.Stats()` + janitor panic-recovery (per E-4). Conversation key is
`sha256(modelID + "|" + tokenID + "|" + firstUserMessage)` with canonical-JSON multimodal hashing
(per A-1, A-2). Integrate it into `ModelsManager` (engine ownership, event-bus subscription,
`ResolveInternalConfigWithAffinity`, `Engine()` accessor) so Phase 3 has a complete, nil-safe seam
to wire into the proxy — **without touching `pkg/proxy` or `pkg/ultimatemodel`** (dispatch boundary
contract).

## Design notes the implementer must honor (from the contract, non-negotiable — AMENDED 2026-08-21)

> **AMENDED 2026-08-21 (E-1, E-2, E-3, W-1, W-2, W-3, E-4):** the rules below are the amended contract
> (canonical Locking Discipline table at `technical-analysis.md` lines 990-999); they supersede any
> contradicting design note in the pre-amendment contract.

1. **Locking discipline table** (technical-analysis §Concurrency Model — AMENDED E-1): happy path outer
   RLock → modelState RLock; first-selection upgrades to modelState Lock; `OnModelChanged`/janitor take
   the outer write/RLock per the table. **`OnModelChanged` (AMENDED E-2)** takes outer Lock and
   **filters** bindings (preserve survivors whose credential is in the new list; drop only orphans) —
   NOT clear-all. **Janitor (AMENDED E-1)** takes outer **RLock** + per-model write locks one at a
   time (reads proceed concurrently). **Never hold two modelState locks simultaneously**; acquire outer
   before any modelState lock.
2. **Defensive lookup check** — `GetOrSelect` verifies the binding's credential is still in the
   model's configured list on every hit; stale ⇒ drop + re-pick. This makes missed invalidation
   events self-healing within one request.
3. **No `sync.Map`** — explicit RWMutex (house style, opposite access pattern).
4. **Engine imports**: stdlib + `pkg/models` (for `CredentialRef`) only. No `pkg/proxy`,
   `pkg/store`, `pkg/events` — invalidation reaches the engine via method calls;
   `model.credentials.changed` subscription lives in `ModelsManager`.
5. **`ErrNoCredentials`** exact sentinel: `errors.New("credentiallb: model has no credentials")`.
6. **TTL defaults** 24h / 5m sweep — constructor-tunable (tests use 100ms).
7. **In-memory only** — no DB persistence of bindings in v1 (decisions.md §C Restart Stickiness);
   restart loses bindings (accepted; first request per conversation re-selects).
8. **Single-credential fast path (AMENDED E-3) returns the credential without weighted random AND
   WITHOUT ANY MAP WRITES** — byte-identical behavior to pre-LB; binding-map size remains 0.
   Test asserts binding-map size == 0 after the fast-path call (decisions.md §E test #7 / success
   criterion #5 is the law — the previous "write-once binding" choice is REVERSED).
9. **`GetOrSelect` signature (AMENDED W-1)** is `func (e *Engine) GetOrSelect(modelID, conversationKey string) (credentialID string, newlyBound bool, err error)`. `newlyBound=true` ⇔ a fresh binding was created; `newlyBound=false` ⇔ an existing (in-TTL) binding was reused OR the fast path returned directly OR an empty-key call returned a fresh pick. **Phase 3 publishes `model_credential_selected` ONLY when `newlyBound=true`.**
10. **Empty conversationKey (AMENDED W-2)** ⇒ **NO binding stored**; the engine performs a fresh
    weighted pick per call. The ""-as-own-bucket reading is REMOVED. Empty-key behavior is the
    no-affinity degenerate path. Caller MUST NOT expect affinity for empty-key requests.
11. **W-3 (constructor-only injection)** — verified: this phase has **no `Config.CredEngine`
    references** (phase2 is engine-side; the contract's `Config.CredEngine` field belongs to
    phase3's `pkg/proxy/handler.go`, and phase3 already enforces constructor-only injection — nothing
    for phase2 to remove).
12. **Per-model RNG (AMENDED E-4, recommended)** — each `modelState` owns its own `*rand.Rand`
    (or `math/rand/v2` source), seeded from the engine's `rngSeed` XORed with the model ID hash
    (or via a small seeded sub-source). This removes first-selection contention across models
    (the pre-amendment shared RNG + dedicated mutex is fine but serialized). `Engine.Stats()`
    returns per-model hits/misses/binding-count. Janitor wraps the sweep body in `defer recover()`
    + WARN log. E-4 is **non-blocking for merge** but in-scope for Phase 2.
13. **C2 boundary (REVISED 2026-08-21 — reviewer pass):** the engine does **NOT** publish a
    DEBUG log or event for empty-key fresh picks. `newlyBound` is the only signal — empty-key
    picks return `NewlyBound=false` (no binding stored, per C2); phase3 reads `NewlyBound` and
    decides whether to publish `model_credential_selected`. The binding-store side effect is
    what `NewlyBound` reports; the engine has no other observable side effect for empty-key
    fresh picks. **Phase 3 owns observability for empty-key fresh picks** (cheap, per-request
    DEBUG log). Adding an engine-side DEBUG log here would re-introduce silent hotspot risk
    (per Risk P2-7). This boundary is part of the contract — engine MUST NOT emit a
    binding-related log/event for empty-key calls.
