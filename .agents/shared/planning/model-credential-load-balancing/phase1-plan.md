## Objective

Add `models.credentials_json` (ordered, weighted JSON array) alongside the existing
`models.credential_id` (kept as a **derived shadow** per M-1 — same-statement `UPDATE` write) across
the persistence layer and shared types: one dual-dialect atomic migration (028, **no DROP**),
`ModelConfig.Credentials []CredentialRef` (the old `CredentialID` **struct field** is removed; the
underlying `credential_id` **column stays**), `ModelsManager` CRUD/validation/in-use-guard/scan
rewritten, and a mechanical compile-shim sweep so every package that read `model.CredentialID` keeps
building and behaving identically for single-credential models. At the end of Phase 1 the whole repo
compiles, all existing tests pass (fixtures migrated), a single-credential model round-trips through
the store with byte-identical resolution behavior, **the shadow write is exercised by the CRUD test
suite**, **and the PG-gated 028 file-level transaction test passes** (MANDATORY gating — 028 is the
repo's first file-level `BEGIN…COMMIT` migration; PG 024's only `BEGIN` is inside PL/pgSQL).

**Authoritative refs:** `technical-analysis.md` §API Contract (`pkg/models` types, store-layer
changes, Migration SQL at lines 696-892 — **AMENDED**), §Backward Compatibility Matrix, §Risks #12;
`decisions.md` §B (schema), §D (fast path), §B Migration Numbering. Line numbers below were verified
against the working tree on 2026-08-21.
