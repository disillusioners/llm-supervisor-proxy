# Phase 3: Handler & Runtime Wiring

## Objective
Wire the `pkg/credentiallb.Engine` (delivered by Phase 2) into the live request path so every internal-model chat completion picks one of the configured credentials via conversation-sticky weighted load balancing, while keeping single-credential models byte-identical to today. Concretely: extend the proxy/ultimate handler signatures (7th constructor param for the engine; no `Config.CredEngine` field per W-3), cache `rc.firstUserMessage` in `initRequestContext` and compute the token-salted `rc.conversationKey` at the post-auth wiring site (`handler.go:401+`, where `rc.tokenID` lands — A-1), swap the two `ResolveInternalConfig` call sites for `ResolveInternalConfigWithAffinity(modelID, conversationKey)`, construct + subscribe the engine in `cmd/main.go`, and emit `model_credential_selected` ONLY when the engine returns `newlyBound=true` (W-1 — first-binding signal, not per-request bool). The Anthropic `/v1/messages` internal path (`pkg/proxy/internal_handler.go:67/69` via `handler_anthropic.go:447/461`) gets the same treatment — C1.
