## Objective

When a client request carries header `x-proxy-interleaved-thinking: true|1` AND the resolved upstream credential satisfies `strings.ToLower(cred.Provider) == factory.ProviderMiniMax` (`pkg/providers/factory.go:17`), the proxy translates MiniMax's wire-format `reasoning_details` (array of typed entries) into the OpenAI-compatible per-message `reasoning_content` string on the response side, and on the request side maps each `messages[i].reasoning_content` (string) to `messages[i].reasoning_details` (array, strip-and-replace) AND injects `reasoning_split: true` at the top body level — across all four paths (race-external, race-internal, ultimate-external, ultimate-internal) — while leaving every other combination byte-identical to today's behavior. On the response side, when upstream emits BOTH `reasoning_details` and `reasoning_content` (Q2 "yes" mode), `reasoning_details` WINS and `reasoning_content` is ignored at extraction time (single-winner rule, applied at provider-level extraction on typed paths, translator-side on byte paths — consistent outcome).

A single sentence that, when true, marks the feature complete: *"For a MiniMax credential, a client that sets `x-proxy-interleaved-thinking` sees `reasoning_content` deltas on stream and a `reasoning_content` field on non-stream, with no `reasoning_details` leak; a client that omits the header, or any client hitting a non-MiniMax credential, observes byte-identical responses to today on all four paths. **More precisely:** the flag gates request-side translation (byte-identical request body when off); response-side extraction is data-driven and naturally inert for non-MiniMax upstream (R4) — non-MiniMax responses carry no `reasoning_details` array to extract, so the openai.go parser is a no-op and the translator is not invoked."*

## Scope

### In Scope

1. New translator module `pkg/proxy/translator/minimax.go` (+ stream helper `minimax_stream.go`) exposing the **site-matched API set from architecture §2.3** (NOT a single `[]byte`-canonical surface — the real Anthropic precedent is mixed-type per shape, `request.go:14` typed-struct-in/map-out, `response.go:11` bytes). **Scope: external paths only** (race-external + ultimate-external; see D2 — internal paths extract at the provider layer instead). **(request side)** `TranslateRequestBody(map[string]any) error` (core, in-place mutation), `TranslateRequestBytes([]byte) ([]byte, error)` (bytes wrapper), `TranslateMessagesReasoning(map[string]any) error`, `InjectReasoningSplit(map[string]any) error`; **(non-stream response side)** `TranslateNonStreamResponseBody(map[string]any) error`, `TranslateNonStreamResponseBytes([]byte) ([]byte, error)`; **(stream side)** `type StreamTranslator struct{...}` per-stream instance with `NewStreamTranslator()` and `ChunkBytes(line []byte) (stripped []byte, emitted [][]byte, err error)` — `err` is never fatal. Godoc on every exported function: "not goroutine-safe; gate is caller's job". **Note: `TranslateNonStreamResponseTyped` is NOT exposed** — internal typed paths extract in `pkg/providers/openai.go` (D2); this avoids the `struct→bytes→re-parse→re-encode` double-serialization that the prior typed variant was invented to avoid.
2. **D1 — typed transport for internal paths.** Add an explicit typed field `ReasoningSplit *bool \`json:"reasoning_split,omitempty"\`` on the provider request struct in `pkg/providers/interface.go` (chat-completion request type). No MarshalJSON tricks, no `Extra` reuse. Pointer type so false-vs-absent stays distinguishable if ever needed. The converter (or pre-converter hook) sets this field; `openai.go`'s marshaler picks it up on the wire. Keep `ReasoningDetails []ReasoningDetail` on `providers.ChatMessage` (`interface.go:43-50`) — needed for request-side carry-through so per-message `reasoning_details` survives the `map→*ChatCompletionRequest` hydration. **Do NOT add `ReasoningDetails` to `providers.StreamEvent`** (`interface.go:118-126`) — D2 makes it dead surface (openai.go's stream parser extracts reasoning_details and emits one `thinking` StreamEvent per entry directly).
3. **D2 — provider-level extraction for internal paths.** `pkg/providers/openai.go` is the typed-path extraction point (NOT the translator). Stream parser emits one `thinking` StreamEvent per `reasoning_details` entry (reusing the existing emitter; consumed by the unchanged `case "thinking"` handlers at `race_executor.go:509` and `handler_internal.go:264`). Non-stream internal: same extraction at `extractNonStreamContent` / response-assembly level so `reasoning_details` → `reasoning_content` in the typed response. Single-winner rule applied here too — when both `reasoning_details` and `reasoning_content` are present in the upstream response, `reasoning_details` wins and `reasoning_content` is ignored. Translator is not invoked on internal response paths.
4. Header-only flag `x-proxy-interleaved-thinking` parsed at `pkg/proxy/handler.go` entry (`:465-469` precedent; mirror value-list), stored as `rc.interleavedThinking bool` for race paths; **explicit `interleaved bool` parameter threaded through coordinator→executor signatures** (B3 — `executeInternalRequest(ctx, cfg, rawBody, req)` receives neither `rc` nor `*http.Request`, so the rc-only premise is false). On ultimate paths: `ultimatemodel.Execute` re-parses the header and passes `interleaved bool` down to `executeInternal`/`executeExternal`. Dormant twin C (`pkg/proxy/internal_handler.go:272`) is **explicitly de-scoped** — see B3 below.
5. **D3 — ultimate-external provider gate derived from credential when available.** When `modelCfg.CredentialID` is set, resolve via `config.ModelsConfig.GetCredential(...).Provider`; gate fires iff `strings.ToLower(provider) == factory.ProviderMiniMax` (case-insensitive comparison, follow `handler_anthropic.go:297` `strings.ToLower` precedent; the `factory.ProviderMiniMax` constant at `pkg/providers/factory.go:17` is the canonical reference value). When `modelCfg.CredentialID` is empty/unset, gate = false (no inference from model name). **Operator requirement documented:** attach a credential to the ultimate external model for the feature to activate; P3-5 test fixture attaches a credential for the MiniMax case.
6. **D4 — NARROW header strip on BOTH external paths.** Strip exactly `x-proxy-interleaved-thinking` (case-insensitive) on:
   - `pkg/ultimatemodel/handler_external.go:79-87`
   - `pkg/proxy/race_executor.go:163-166`

   The existing general `x-llmproxy-*` strip at `race_executor.go:163-166` is unchanged. **REJECTED:** adding a general `x-proxy-*` strip would change flag-absent forwarding behavior — violates the critical invariant (old clients never send `x-proxy-interleaved-thinking`, so the narrow strip keeps flag-absent forwarding byte-identical). Update P3-2 header assertions to assert zero `x-proxy-interleaved-thinking` only.
7. Request-side translation for all four paths:
   - **External paths (race-external, ultimate-external):** `messages[i].reasoning_content` (string) → `messages[i].reasoning_details` (MiniMax array format) before forwarding upstream via the translator (`TranslateMessagesReasoning` on maps; `TranslateRequestBytes` on bytes). Mapping is **strip-and-replace**: build `reasoning_details = [{type:"reasoning.text", id:"reasoning-text-<n>", format:"MiniMax-response-v1", index:0, text:<string>}]` (n = per-message counter starting at 1); set `reasoning_details` on the message; delete the original `reasoning_content` field. Empty/absent `reasoning_content` ⇒ message untouched (no empty array injected). Symmetric with the response-side strip in R11.
   - **Internal paths (race-internal, ultimate-internal):** the converter (or a pre-converter hook) sets `ReasoningSplit *bool = ptr(true)` on the typed `*ChatCompletionRequest`. Per-message `reasoning_details` are populated on `providers.ChatMessage` from the ingDetail` on `ChatMessage`, the typed marshaler carries the array to the wire).
   - Top-level body field `reasoning_split: true` injection (Q8, R7). External paths: via `InjectReasoningSplit` (or `TranslateRequestBytes`). Internal paths: via the typed `ReasoningSplit *bool` field (D1) — the openai.go marshaler emits it. Both transformations funnel through their per-path transport.
8. Response-side translation for all four paths:
   - **Internal paths (race-internal, ultimate-internal):** provider-level extraction in `pkg/providers/openai.go` (D2). Stream: stream parser emits one `thinking` StreamEvent per `reasoning_details` entry; the existing `case "thinking"` consumer emits client chunks with `delta.reasoning_content`. Non-stream: `extractNonStreamContent` / response-assembly maps `reasoning_details` → `reasoning_content` on the typed `ChatMessage`; `omitempty` on `ReasoningDetails` ensures the typed response writes only `reasoning_content`.
   - **External paths (race-external, ultimate-external):** translator operates on bytes/maps per `TranslateNonStreamResponseBytes` / `TranslateNonStreamResponseBody` (non-stream) or `StreamTranslator.ChunkBytes` (stream). Non-stream: read upstream JSON, for each choice mutate `message.reasoning_details` → `message.reasoning_content`; strip `reasoning_details`. Stream SSE: per-entry emission in array order (`reasoning_details[i].text` → `delta.reasoning_content` per client chunk); strip `reasoning_details` from chunk before write.
   - **Single-winner rule (D2):** on internal paths, applied at extraction time (openai.go ignores `reasoning_content` when `reasoning_details` is present); on external paths, applied translator-side (skip entries whose text is contained in `reasoning_content`). Consistent outcome either way.
9. Backward-compat invariants (R1) verified by per-path unit tests asserting byte-identical output for: (a) flag absent, (b) flag present but non-MiniMax upstream. **12 negative-case body assertions** (3 × 4 paths) + **per-path outbound-header assertions** (zero `x-proxy-interleaved-thinking` keys, per D4).
10. E2E coverage using MiniMax mock-server harness pattern from `test/test_mock_ultimate_model.sh` and `test/e2e_ultimate_internal_reasoning/`.
