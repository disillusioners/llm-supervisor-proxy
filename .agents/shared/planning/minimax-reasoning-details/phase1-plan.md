# Phase 1: Request-Side Translation

## Objective

Land the foundational translator module, struct fields, flag plumbing, and provider gate so that:
1. A MiniMax-flagged request carries `reasoning_split: true` at the top level of the outbound body AND each `messages[i].reasoning_content` string is mapped to a `reasoning_details` array across all four paths.
2. A non-MiniMax or non-flagged request is byte-identical to today on all four paths (gate short-circuits BEFORE any parse/marshal on verbatim paths — see H5).
3. The struct surface (`providers.ChatMessage.ReasoningDetails`) is in place so Phase 2 can preserve `reasoning_details` through marshal/unmarshal on internal paths. `providers.StreamEvent.ReasoningDetails` is **NOT** added (dead surface — stream translator operates on chunk bytes per §5.2 H9).
4. Header strip is added so `x-proxy-interleaved-thinking` and `x-llmproxy-*` headers do NOT leak to upstream MiniMax on ultimate-external (H1, critical).

This phase does NOT translate response bodies — that is Phase 2. Phase 1 only wires request-side mutation and the shared scaffolding.

---

## Prerequisites

- `pkg/proxy/translator/` directory exists (Anthropic precedent already in place — `request.go`, `response.go`, `stream.go`, `types.go`, `tools.go`, `errors.go`, `translator_test.go`).
- `pkg/providers/interface.go` is the typed-shape source of truth.
- `pkg/proxy/handler.go` parses `X-Force-Ultimate-Model` at `:465-469` — the precedent to mirror.
- Technical analysis (`.agents/shared/planning/minimax-reasoning-details/technical-analysis.md`) is the binding source for hook points and decisions R1-R11 + Q1-Q11.

## Coupling

- **Tight with Phase 2** — Phase 2 reads the flag via the dual mechanism from P1-6 (race: `rc.interleavedThinking`; ultimate: `interleaved bool` parameter); `ChatMessage.ReasoningDetails` is **request-side carry only** (populated by P1-4b on the request side; never consumed by the response-side path — D2 moves response extraction to `pkg/providers/openai.go`'s parser and `extractNonStreamContent` / response-assembly, so internal typed `Encode(resp)` sites get `ReasoningContent` populated at parse time without any translator call); Phase 2 calls `translator.TranslateNonStreamResponse{Bytes,Body}` (NOT `{Bytes,Body,Typed}` — the typed variant is REMOVED per D2) / `translator.NewStreamTranslator().ChunkBytes` defined as siblings of the request-side functions. The translator module is the shared single source of truth on **external paths only**.
- **Loose with Phase 3** — Phase 3 unit-tests the translator functions and the byte-identical negative cases (P1-9); e2e tests verify request-body shape on mock upstream.
- **Independent of** other phases not listed.

## Exit Criterion

Phase 1 is DONE when **all** of the following hold simultaneously:

1. `go build ./...` and `go vet ./...` pass with no warnings introduced.
2. Existing unit tests pass without modification (backward-compat invariant #1 + #5 + #6).
3. New unit tests for P1-5 (header parsing) and P1-9 (negative-case byte-identical on all 4 paths) pass.
4. Drift trap check (P3-3 AST test) passes — no `reasoning_details`/`reasoning_split` mutations outside `translator/` in the 4 call-site files.
5. `executeExternal` signature includes the threaded `upstreamProvider string` (R3 mitigation) and its sole caller has been updated.
6. **`executeExternal` header loop strips exactly `x-proxy-interleaved-thinking`** (case-insensitive, H1 fix per binding D4 — narrow strip on BOTH external paths; general `x-proxy-*` strip REJECTED); P3-2/P3-5 header assertion passes.
7. `providers.ChatMessage.ReasoningDetails` exists with `omitempty`; a round-trip test on OpenAI-shape JSON shows zero diff vs pre-change baseline. `providers.StreamEvent.ReasoningDetails` does NOT exist (verified by `grep`).
8. `parseInterleavedThinkingHeaderValue` is the single source of truth for accepted values, used by both `handler.go` and `ultimatemodel.Execute`.

Once Phase 1 exits, Phase 2 can begin (it depends on the translator module, the struct fields, the flag plumbing, and the credential thread).
